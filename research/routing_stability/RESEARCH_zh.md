# QuantumGate 的潜在优势与 MoE 路由数值稳定性

调研及本机诊断日期：2026-10-28（Asia/Shanghai）。本文区分已观测结果、公开研究结论与待验证设计。原有分类/自回归正式实验、权重和冻结训练代码均未改动；本轮只运行 checkpoint 前向诊断，没有新训练。

**判断：当前已经证明“这类门可训练、可接入、能获得接近基线的效果”，尚未证明“比强经典基线更好”。下一步最值得验证的是参数—性能—稳定性—延迟的联合折中，尤其是低精度输入下的路由一致性。** 直接以 quantum 命名、状态归一化或者幺正演化，均不能推出 top-k 专家稳定。

原自回归实验中，Born half 的测试 PPL 为 79.84±0.93，half MLP 为 79.48±1.98；前者路由参数进一步少9.6%，但每步约慢51%，整个模型只再少0.154%。这意味着我们需要寻找实质的新用途，或减少当前线路的执行开销。原结果见[完整实验报告](../../outputs/autoregressive_gate/REPORT_zh.md)。

**一、相关研究提供了哪些方向**

| 研究方向 | 直接证据 | 对本项目的意义与边界 |
|---|---|---|
| TN 的结构性参数压缩 | Stoudenmire & Schwab 用 MPS 参数化非线性学习模型。[NeurIPS 2016](https://papers.neurips.cc/paper_files/paper/2016/hash/5314b9674c86e3f9d1ba25ef9bb32895-Abstract.html) | χ 控制可表达的相关结构，可能以较少参数获得合适的归纳偏置；论文不是语言模型 router 的优势证明。 |
| 数据重上传的非线性特征 | Pérez-Salinas 等给出重上传量子分类器；Schuld 等说明输入编码决定可访问的 Fourier 频率。[重上传](https://arxiv.org/abs/1907.02085)、[Fourier 分析](https://arxiv.org/abs/2008.08605) | 可尝试用少量旋转参数表达有用的交叉/周期特征；频率更丰富也可能更敏感，不意味着泛化和稳定性自动改善。 |
| 可约束的输入敏感度 | Berberich 等推导依赖可训练编码的 Lipschitz 界，提出编码范数正则。[PR Research 2024；arXiv 最新版本](https://arxiv.org/abs/2311.11871) | 与本问题最直接相关。应约束输入投影/角度生成的敏感度，而非只检查线路是否幺正。 |
| 量子分类器的鲁棒性 | Dowling 等研究弱扰动、局部攻击和普适攻击下的条件性保护。[npj Quantum Information 2026](https://arxiv.org/abs/2405.10360v2) | 说明鲁棒性可以是精度/速度以外的研究维度；这些假设不能直接覆盖本项目的经典编码、浮点 kernel 和 hard top-k。 |
| 直接的 Quantum MoE 探索 | Heddad 等的 QMoE 预印本在 Two Moons、降维二分类图像上报告较少路由参数的结果。[QMoE，2025](https://arxiv.org/html/2512.22296v1) | 是动机，证据较弱：小型模拟任务、主要展示对线性路由的改善；深非线性基线分差小，尚不能推出 LLM 或本机吞吐优势。文中的量子退极化噪声与浮点路由错位不是同一个问题。 |

应保留强经典对照。Bowles 等对12类量子模型和160个小数据集的研究发现，经典方法整体更强，移除纠缠常不降低表现。[基准研究，2024](https://arxiv.org/abs/2403.07059) 这不否定我们的方向，但说明“优于弱线性模型”不足以证明量子结构的贡献。

可挖掘的优势按优先级排序如下；都是待验证假设。

1. **低精度部署鲁棒性。** 相同 PPL/延迟下，降低 hidden-state 舍入或计算路径变化引起的专家切换，并减少大幅 logprob 变化。
2. **小预算下的参数效率与泛化。** 比较预算从 full、half 到 quarter 的 Pareto 曲线，包含 half/quarter MLP、低秩线性、平方读出、正交网络；区分整个模型与 router 参数。若只在更小训练集上获益，应报告这种适用范围。
3. **以较少结构参数表达专家间的组合关系。** 需要 matched-rank、同预算的有/无 CRY 对照，并测试专家编号重排的敏感性。二进制编号赋予专家的“邻接”未必有语义；路由 Shannon 熵也不是量子纠缠熵。
4. **可解释、可控制的敏感度约束。** 能给每个 token 一个“距离路由切换还有多远”的指标，比单独看平均准确率更有用。但同类约束也能在经典网络中实现。

当前联合幅度读出仍处理 E 个幅度，输入投影约 O(Dr+rE)，浅线路模拟约 O(E·q·depth)，q=log2(E)。不能因只有 q 个量子比特就宣称整体仅 O(log E)，更不能忽略经典数据编码、完整读出和 GPU kernel 常数开销。若真在量子硬件采样，概率估计的 shot noise 反而需要另行处理；本次实测均为确定性状态向量模拟。

**二、用户提到的训练/推理错位是真问题，但需要分清来源**

浮点数不满足结合律；批次大小、矩阵形状、归约顺序或 kernel 不同，即使权重和输入相同，也未必逐位相等。PyTorch 明确说明批量计算与逐样本计算可能不同；Thinking Machines 的工程研究强调，单次执行可重复并不等于对 batch 大小不变。[PyTorch 2.6 数值说明](https://docs.pytorch.org/docs/2.6/notes/numerical_accuracy.html)、[批次不变性研究](https://thinkingmachines.ai/blog/defeating-nondeterminism-in-llm-inference/)

```mermaid
flowchart LR
    A[相同权重与相同文本上下文] --> B[批次形状 / 精度 / kernel变化]
    B --> C[hidden或router分数出现微小差异]
    C --> D{第k与k+1名接近?}
    D -- 是 --> E[top-k专家集合变化]
    E --> F[不同专家输出使差异放大]
    F --> G[后续层 / token概率 / RL比率改变]
    D -- 分差足够大 --> H[专家集合保持]
```

需要分别测量四类现象：同权重同上下文的数值差异；容量限制造成的批次竞争；训练时 dropout/jitter 与推理关闭的语义差异；优化器更新/异步参数陈旧导致的真实策略变化。后面三类不能统一归咎于浮点数。本项目正式配置无 gate dropout/jitter、无 token dropping；新的诊断全部用 eval 模式，隔离第一类。

R3 研究直接分析了 MoE 训练与 rollout 路由差异，并使用记录和重放专家选择来缓解 RL 不稳定。[R3，2025](https://arxiv.org/abs/2510.11370) NVIDIA 现有实现也提供 Router Replay，并重新计算当前权重的路由分数，而重放离散专家选择。[NeMo 文档](https://docs.nvidia.com/nemo/rl/nightly/guides/router-replay.html) 它是工程基线，不是 QuantumGate 独有功能，也不保证隐藏状态/混合权重逐位一致。

较新的 RDC 预印本提醒，异步训练和权重更新后，强行重放旧路由会相对当前原生路由改变梯度归属。[RDC，2026-10-15](https://arxiv.org/abs/2610.21682) 所以数值一致性与策略真正变化应分开统计；不能把所有专家变化都消除。

Switch Transformer 的局部 FP32 路由与 ST-MoE 的 router z-loss 是基础对照，它们主要针对计算/优化稳定性，而非证明任意两种执行条件下专家集合相同。[Switch Transformer](https://jmlr.org/papers/v23/21-0998.html)、[ST-MoE](https://arxiv.org/abs/2202.08906)

已有研究把结构对齐直接用于量化：VSRAQ 在校准目标中保持专家次序和 top-k 边界，不改变推理图。[VSRAQ，2026-06](https://arxiv.org/html/2606.05688v1) 因此“加边界损失”本身不应作为新颖量子机制；我们的研究问题是量子式结构是否在同预算下额外改善这种折中。另有 Elastic Expert Routing 用训练时随机活跃专家预算缓和曝光边界，但那不是确定性专家一致性的保证。[EER，2026-10](https://arxiv.org/abs/2610.11575)

**四、为什么 Born 本身不保证稳定**

下面是本报告针对路由问题的直接推导，不是对某篇论文结论的扩大引用。分数按降序为 s_(1)…s_(E)，定义边界间隔

\[
m(x)=s_{(k)}(x)-s_{(k+1)}(x).
\]

若两次计算逐专家分数的差有界 \(\|s'-s\|_\infty\le\epsilon\)，则

\[
m(x)>2\epsilon\quad\Longrightarrow\quad\mathrm{TopK}(s')=\mathrm{TopK}(s).
\]

理由是已选最小分最多下降ε，未选最大分最多上升ε。m=0或非常小时，任何连续打分器后面接 hard top-k 都可能切换。可以先减去每行均值消除不影响排序的共同偏移，再用这个充分条件。本轮代码对此做了逐项断言；使用的是实际测得的两次分数误差，并非跨硬件、未知扰动的事前认证。

当前实现中，\(s=g\log[(p+f)/(1+Ef)]\)，g为正，最终温度T为正。因此在精确算术下，top-k(s)、top-k(p)、top-k(p^(g/T))集合相同。仅降温、放大gain、给全部概率加同一个floor，都不会改变相同输入下的排序，也不能根治输入扰动造成的边界反转。过小floor仍可能让log的导数变大；去掉log/softmax后也仍有hard top-k。

固定、与输入无关的幺正/正交 U 满足

\[
\|U\psi-U\phi\|_2=\|\psi-\phi\|_2,\qquad
\max_i\big||\psi_i|^2-|\phi_i|^2\big|\le2\|\psi-\phi\|_2
\]

（ψ、φ为单位向量）。若编码器的局部/域内敏感度有界 \(\|\psi(x+\delta)-\psi(x)\|_2\le L_{enc}\|\delta\|\)，则 Born概率的边界间隔大于 \(4L_{enc}\|\delta\|\) 是理想算术下的一个保守充分条件。若概率计算还各有误差，则另加对应数值误差余量。这条界说明可利用“受控编码+非放大演化”，并不说明它优于经典正交网络。

现有 AmplitudeReuploadBornGate 的 U 实际也随输入角度变化，有

\[
\|U(x')\psi(x')-U(x)\psi(x)\|_2
\le\|\psi(x')-\psi(x)\|_2+\|U(x')-U(x)\|_{op}.
\]

所以必须约束 amplitude/angle投影、LayerNorm增益以及编码敏感度。当前tanh有界、初始幅度在(0.5,1.5)有助于避免零范数，但投影权重、LayerNorm低方差输入的导数仍需考虑；线路幺正性本身不够。Born测量后的离散决策更不是连续映射。

**五、建议优先验证的两项设计**

**方案A：在现有 half Born 与 half MLP 上都加入边界训练。** 这最接近“推理不增加计算复杂度”的要求。用预增益概率间隔，或平移/缩放不敏感的标准化分数

\[
\hat s=\frac{s-\bar s}{\mathrm{RMS}(s-\bar s)+\eta},\qquad
L_{margin}=\lambda\mathbb E[\max(0,\tau-(\hat s_{(k)}-\hat s_{(k+1)}))^2].
\]

归一化分母参与求导，防止简单放大gain就满足约束。τ由训练侧数值误差校准与内部dev选择，不根据最终test调整。训练时取k+1个分数；推理时移除这个loss分支，仍然只选k个专家。可以用小比例token的舍入输入再跑一次router，补充top-k边界/概率一致性损失；这个训练开销必须测量，不能称免费。早期探索充分后再逐渐提高λ，防止一开始锁死随机专家；同时监控负载与PPL。

它有可能改善稳定性，但 margin增大可能牺牲边界附近的有用适应能力、均衡或预测性能，没有“不掉分”的数学保证。必须在两类gate上使用同样损失，防止把训练策略的收益误认作Born优势。只最小化切换率会让恒定路由成为退化解，任务损失和专家利用率必须同时约束。

**方案B：更便宜、敏感度更清晰的幅度 Born。** 保留联合幅度编码，去掉每token数据重上传角度，使用少量共享参数构成的浅正交/RY-CRY层，直接用平方幅度排序和归一化权重：

```mermaid
flowchart LR
    X[每token的D维输入] --> P[受控投影与非线性]
    P --> A[E维有界联合幅度]
    A --> N[L2归一化]
    N --> U[输入无关的浅RY / CRY或正交层]
    U --> Q[平方幅度 p]
    Q --> K[top-k专家与归一化权重]
    Q -. 仅训练 .-> M[边界间隔损失]
```

共享U只要求对token输入固定，训练中仍可学习参数。E=16/64时可将共享浅线路预先收缩为小矩阵做GEMM，或融合成蝶形旋转kernel；到底更快需端到端测量。与当前逐token计算角度和多次小算子相比，减少的运算很具体，但可能损失表达能力，必须重新训练独立分组。当前可学习g不能随意删掉：原混合权重正比于(p+f)^(g/T)；仅在g/T=1时可严格简化成直接概率归一化。top-k可以直接在p上选，但有限精度下ties仍需验证。

必要的对照是：无U平方归一化路由、同预算经典正交路由、无CRY、原始数据重上传Born，以及half MLP。若U前后都是可合并线性映射且没有中间非线性/约束，则U可能只是重参数化，不应把它当新表达能力。本方案保留幅度非线性以避免这一简单吸收，同时仍不能预设纠缠收益。

对于MPO，范数不自动保持，可通过训练时的谱范数约束/投影控制放大。推理权重固定后不需要每次重新做谱分解。这个经典方案也应与Born一起竞争，不能只为Born配置正则。

**六、低成本工程手段与明确不建议的捷径**

| 手段 | 可解决什么 | 不能承诺什么 |
|---|---|---|
| router计算保持FP32，统一norm/softmax/精度策略 | 降低router内部舍入误差 | 不能恢复上游已经丢失的hidden信息，也不能保证batch不变性 |
| 对完全相等的分数按专家ID确定性决胜 | 消除真正ties的实现歧义 | 近似相等但已反转的分数仍会换专家；稳定排序有实测成本 |
| 训练时margin/编码范数约束 | 让常见输入远离敏感边界，推理图可保持不变 | 不能事前保证PPL不变或所有输入稳定 |
| 小分差时走一致的FP32/固定归约fallback | 只在少数危险token上付出代价 | 需真实误差界/校准；两引擎都要实现同一策略，触发率可能变化 |
| RL Router Replay | 对已生成样本保证重放相同专家ID | 存储/传输有成本；不消除权重陈旧，不能代替所有数值一致性措施 |

不建议把“低温”“随机采样专家”“概率量化”“对上一token沿用专家”当作通用修复。低温不改变排序；随机采样引入额外不确定性；量化把边界移到量化格点并可增加ties；沿用上个token混淆了不同语义输入。固定epsilon乘专家ID的微小偏置也可能直接改变真实近邻次序，优先用明确的tie规则而非任意偏置。[PyTorch topk 对ties的说明](https://docs.pytorch.org/docs/2.14/generated/torch.topk.html)

任何依赖输入的非恒定hard top-k映射都有决策边界。可争取的是“目标分布与规定误差范围内的可靠性”，不是任意扰动下零切换、任意硬件上完全一致且零代价的普遍保证。

**七、下一轮如何得到可信结论**

先复用本次诊断协议做校准，随后在独立配置下比较 half MLP / half Born / Born简化版，各自有无margin训练；必要时加正交平方读出对照。先小pilot检查梯度、负载、预算和延迟，再以相同步数、token、batch、共享初始化和种子运行。新增训练尚未实施。

预先写明验收指标：等token CE/PPL及配对差；等时间曲线；同输入同权重的路由集合切换率、替换专家比例、边界间隔分位数；教师强制下的词表/目标logprob误差和大误差尾部；真实训练与部署精度组合；router/整模型端到端延迟、显存、fallback触发率；负载CV和未使用专家。不能只看路由熵，也不能把token间相关观测当作独立样本扩大显著性。

作为待预注册的工程门槛，可先考虑：相对同预算MLP的PPL劣化不超过0.5%，端到端延迟不超过5%，在预定精度条件下切换率明显降低（例如目标减半）。这些数值是建议目标，不是实测承诺；若原始切换接近零，应以绝对事件数/误差尾部和足够样本量为主。三种子不足时扩展种子；“差异不显著”不能代替非劣性验证。验证集用于选λ/τ，后续还应加入新语料或保留新的确认集，避免根据已经看过的WikiText test反复优化。

部署路径测试要逐级推进：本机batch形状与输入舍入 → 真实混精度训练/推理 → 可用时跨框架和prefill/decode → 若开展RL再比较R3。TITAN V没有新架构的原生BF16/TF32能力，本次舍入探针不能替代现代GPU测试。我们的 MoTE 张量块专家也不同于大型分布式FFN MoE，因此不能将本机小切换率直接外推到大模型。

**实现检查中发现的两个注意点。** 当前structured gates在禁用autocast区间内用FP32，普通MLP遵循其权重dtype；未来混精度比较必须给MLP相同的FP32 router待遇。本轮原实验和新诊断全部FP32，这不影响现有结果。另外 gate.py 的活跃TopKGate路径用mean(logsumexp)作l_z，没有ST-MoE定义中的平方；当前配置zloss_coeff=0，所以既有结果不受影响。但新一轮如用z-loss基线，须在独立修订中实现并验证标准的mean(logsumexp²)，不能直接打开现有开关后声称复现ST-MoE。此次未更改冻结代码。
