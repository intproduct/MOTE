# PRO 4000 执行任务：Qwen 接入负责人

这是给本机执行代理的任务指令。先读取本目录上级 README、COMMON_PROTOCOL.json、
ENVIRONMENT.md 和 plans/pro4000.json，检查实际仓库、分支、设备及其他进程。
在当前拉取版本上记录 commit。按已获授权的实验计划推进实现和短测，不创建子代理。

## 第一阶段：接入四种 gate

在新目录 `experiments/qwen_joint/` 实现独立 Qwen 联合训练入口，并接入项目包声明。
保留 `experiments/operator_geometry/` 的冻结文件。复用生产 MoTE 替换和保存机制时，
逐项核对 `config/schema.py`、`gate.py`、`sparse_mixt.py`、`ADTN.py`、`train/`、`checkpointing.py`。
当前生产 RouterLogits 支持 MLP 和旧 quantum；最新 affine/CZ/product 尚需集成。

1. 以 Qwen3-0.6B-Base 为起点，明确最后四分之一层的实际编号和三类 FFN 投影。
   先复核 Qwen SwiGLU 布局、张量分解边界和余项。旧小模型的 GELU/256 维布局不能直接替代。
2. 将 `round3_capacity.ReencodingPredictor` 的 affine/CZ/product 数学形式移植到新模块。
   它原来的 forward 返回“越小越好”的 cost；新接口应显式返回越大越好的 logits。
   验证 top-k 索引、归一化权重、tie 处理、FP32 路由及梯度。移除 teacher 拟合遗留的训练依赖；
   原始 cost 符号、尺度与校准幂须有清楚转换，不能凭名称复用。
3. CZ 与 product 保持相同八角编码、相同共享编码器；product 只去掉 CZ。
   MLP 和 affine Born 使用匹配的特征秩，记录真实参数差异；不沿用先前被拒绝的静态专家排列。
4. 每 seed 只构造一次共享专家初始状态，再向四门复制；同一模型内专家保持各自独立。
   在模块输出、任务损失和初始负载上检查替换误差。所有 gate 和专家从首个任务更新共同训练。
5. 必须覆盖保存/恢复、完整模型前向、selected/unselected 梯度、AMP 下路由 FP32、
   相同样本流、实际稀疏 dispatch 和中断续训等测试。单测区分 CPU 数学验证与 GPU 实测。

## 第二阶段：冻结数据和共同 pilot

按 COMMON_PROTOCOL 准备 train/internal_dev/reserved_test 文档级分割。
训练使用原始文本 next-token CE。共同主实验不启用蒸馏、margin 或冻结专家功能 Gram。
显式覆盖旧配置中的 gate_freeze_steps、temperature schedule、数据混合、KD 和 stage 默认值。

先跑四门及 Dense FFN 控制的 20 次更新 smoke，再完成各自相同 token 的 seed17 pilot。
记录损失、router/expert 梯度与更新、负载、吞吐、峰值显存和精确样本清单。
OOM 时优先减 microbatch、激活重算和分块 CE，保留全局有效 token 数与样本次序。
正式 token 预算若因实测成本调整，先统一写新配置和原因，再运行完整矩阵。
